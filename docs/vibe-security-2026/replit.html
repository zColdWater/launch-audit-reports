Top 4 Pre-Launch Risks in Replit Agent Production Apps

1. Missing Helmet & HTTP Security Headers

Express and Flask servers scaffolded by Replit Agent rarely enable Content-Security-Policy, HSTS preload, X-Frame-Options, or Permissions-Policy by default.

2. Secrets Hardcoded Outside Replit Secrets Vault

Accidentally committing API keys into client/src/ or .env files instead of Replit Secrets exposes live Stripe, OpenAI, or PostgreSQL credentials to every visitor.

3. Exposed /swagger.json, /docs & Dev Endpoints

FastAPI /docs, /openapi.json, GraphQL playgrounds, and Express debug routes often stay publicly reachable in production unless gated by NODE_ENV=production.

4. Broad CORS (* + Credentials) & Missing Rate Limits

Setting Access-Control-Allow-Origin: * alongside session cookies or exposing unthrottled LLM endpoints makes Replit apps easy targets for quota draining.

Copy-Paste Express Security Middleware for Replit Deployments

// Drop at top of server/index.js (before route handlers)
app.disable("x-powered-by");
app.use((req, res, next) => {
  res.setHeader("Strict-Transport-Security", "max-age=63072000; includeSubDomains; preload");
  res.setHeader("X-Content-Type-Options", "nosniff");
  res.setHeader("X-Frame-Options", "DENY");
  res.setHeader("Referrer-Policy", "strict-origin-when-cross-origin");
  res.setHeader("Permissions-Policy", "camera=(), microphone=(), geolocation=()");
  res.setHeader("Cross-Origin-Opener-Policy", "same-origin");
  next();
});
