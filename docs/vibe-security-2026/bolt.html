Top 4 Pre-Launch Risks in Bolt.new & Netlify Production Apps

1. Direct Browser Calls to OpenAI / Gemini / Stripe

Prototyping directly in Vite often wires API keys straight into fetch() calls in the browser. Move every paid API call into a Netlify Function, Cloudflare Worker, or Supabase Edge Function.

2. Missing public/_headers Security Policy

Without a public/_headers file, Netlify and Cloudflare Pages deployments lack Content-Security-Policy, X-Frame-Options, Permissions-Policy, and HSTS preload directives.

3. Build Source Maps Left Enabled

Ensure build.sourcemap is false in vite.config.ts before production deploys so attackers cannot reconstruct your full TypeScript source tree from /assets/*.js.map.

4. Unprotected AI Generation Endpoints

Add per-IP rate limiting and strict max_tokens limits on server functions so automated bots cannot drain your LLM API quota overnight.
