Next.js llms.txt Generator Guide (App Router & Static Export) for AI Search Citations

An /llms.txt file gives AI search assistants a curated, noise-free Markdown map of your product, docs, pricing, and API endpoints without forcing crawlers to parse megabytes of client-side JS bundles.

1. Minimal Static /llms.txt (public/llms.txt)

For marketing sites or static exports, place a UTF-8 Markdown file at public/llms.txt. Follow the official llmstxt.org format: H1 brand name, blockquote one-sentence summary, then H2 sections with Markdown links and concise descriptions.

# Acme Analytics

> Privacy-first product analytics and session replay for SaaS engineering teams.

## Core Docs
- [Quickstart Guide](https://acme.example/docs/quickstart): Install the 4 KB script in 2 minutes
- [Pricing](https://acme.example/pricing): Free up to 100k events/mo; Pro starts at $29/mo
- [REST API Reference](https://acme.example/docs/api): Event ingestion & cohort export endpoints

2. Dynamic Next.js App Router Route (app/llms.txt/route.ts)

If your docs or changelog update frequently, serve /llms.txt from a Next.js Route Handler with Content-Type: text/plain; charset=utf-8 and proper cache headers:

// app/llms.txt/route.ts
import { NextResponse } from "next/server";

export const revalidate = 3600;

export async function GET() {
  const md = [
    "# Acme Analytics",
    "",
    "> Privacy-first product analytics for SaaS teams.",
    "",
    "## Key Pages",
    "- [Docs](https://acme.example/docs): SDK setup & SQL query guide",
    "- [Pricing](https://acme.example/pricing): Transparent self-serve tiers",
  ].join("\n");

  return new NextResponse(md, {
    headers: { "Content-Type": "text/plain; charset=utf-8" },
  });
}

Does Next.js App Router support a route folder literally named llms.txt?

Should /llms.txt return text/plain or text/markdown?

text/plain; charset=utf-8 or text/markdown; charset=utf-8 are both accepted by AI crawlers; never return text/html.
